- Two places the ratified route turned out shorter than `ORDER-TYPE.md` anticipated, both
  recorded in that file's log — don't "fix" them back:
  1. **Injectivity of `nonoteCode` needs nothing.** The brief expected a `Nat.pair`-layout
     argument or something from `NotationBridge`. Unnecessary: `precN_code_iff` already forces
     it. If the codes agree, either strict side of `lt_trichotomy` rewrites into
     `precN (nonoteCode a) (nonoteCode a)`, i.e. `a < a`. See `toField_injective`.
  2. **No `WellFoundedRank.lean` dependency.** The source repo
     (`goodstein-independence` branch `kreisel`) routed through a rank function because it only
     wanted `ε₀ ≤ orderType` of a *pulled-back* order on `ℕ`. Here both bounds are wanted and
     `NONote.repr` is available directly, so `range_NONote_repr` upgrades to a genuine order iso
     `reprIso : NONote ≃o Set.Iio ε₀` — and because `NONote`'s `≤` is *definitionally*
     `repr · ≤ repr ·` (mathlib `Notation.lean:1212`, the `Preorder NONote` instance),
     `map_rel_iff'` is literally `Iff.rfl`. Mathlib's `type_lt_Iio` finishes. So the copied
     block shrank to five lemmas.
- **Universe wrinkle, in case it resurfaces:** `Set.Iio ε₀ : Type 1` while `NONote : Type 0`, so
  `RelIso.ordinal_lift_type_eq` hands you `lift.{1,0} (typeLT NONote) = lift.{0,1} (lift.{1,0} ε₀)`.
  A bare `Ordinal.lift_inj.1` type-mismatches; one `simpa` collapses the double lift first.
- **One addition beyond the frozen declaration list**, deliberate: `precF_iff_eval_precCode`.
  Without it, a reader has to trace `precN → precDef → precCode = liftCode precDef` by hand to
  believe the ε₀ is about *Gentzen's* `≺` rather than some lookalike relation. It discharges that
  via `PrecStandard.eval_precAt_numeral`. Keep it in the PR; it is the audit link.
- `ε₀` is scoped notation in `Mathlib.SetTheory.Ordinal.Veblen`, which the repo did not transitively
  import at `Gentzen.CodeSurj`. The new file imports it explicitly.
